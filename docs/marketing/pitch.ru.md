# Venus: питч

[English](./pitch.md) · **Русский**

![Venus](/docs/img/image.png)

**Venus — это spec-driven development:** способ делать софт, когда код пишут агенты.

Люди направляют вкусом, волей, желаниями. Агенты делают работу. Спецификация — запись договорённости. История не закрыта, пока спецификация не актуальна — или вы явно пропускаете шаг, потому что контракт не менялся.

Venus — инструмент для этого способа работы. Это **LLM-вики**: одна спецификация, которую люди пишут вместе, как в Notion, а агенты клонируют, ищут и правят как markdown в git. Это не два продукта. Это одна спецификация.

## Разрыв

Красивый совместный WYSIWYG — для людей. Агенты там не живут. Они живут в **папках markdown в git-репозитории**.

Сегодня этот раскол — дыра:

- Notion и Google Docs: комната может писать вместе. Экспорт — дамп. Агенты не клонируют честное дерево. Если агент печатает в страницу, агент становится записью.
- Confluence: там живёт технический дизайн. Тяжело. Дамп → ChatGPT → Cursor. Те, кто не пишет markdown, не могут править копию.
- Cursor: отлично **пишет** markdown и **код**. Плохо **принимает документ**. В превью нет diff. Коммиты смотришь в исходнике и переключаешь preview/source. Это боль.

Venus закрывает разрыв.

## Как это работает

**Мозговой штурм.** Команда на созвоне в совместном редакторе — нарочно как Notion, чтобы продукт, маркетинг и разработка реально пришли. Пишут спецификацию вместе. Можно **попросить агентов помочь её написать**. Люди по-прежнему печатают в комнате. Агент не становится страницей, печатая в живой документ.

**Снимок.** Venus непрерывно проецирует живую страницу в **git markdown**. Агенты клонируют ту же спецификацию, которую только что написала комната. Без дампа. Без копипаста.

**Правка агента.** Когда агент меняет спецификацию, он правит **markdown**, не живой CRDT. Он предлагает **git-коммит**. Человек принимает, правит или отклоняет. Это цикл Cursor, направленный на вики: checkout, diff, комментарий, accept — только вы смотрите **отрисованное** изменение, а не пометку только в исходнике.

**Почему на каждом решении.** Эти коммиты — настоящий git. У каждого предложения агента есть **комментарий: почему он так решил**. Diff вы видите в WYSIWYG (After / Before / Diff). Не нужно переключать preview и source, чтобы понять смысл.

**Вопрос с контекстом.** В фоне LLM индексирует вики как **семантический граф с осью времени** — как части спецификации связаны и как они эволюционировали. Выделяете фрагмент, спрашиваете: в пак попадают связанные страницы **и** история, почему сделано так, кто решил, какой коммит откатывать.

**План, DoD, прогон.** LLM-вики становится **планом**. Definition of done — это **тесты**: сценарии живут в вики, не чеклистом в тикете. План запускается. Каждый шаг покрыт тестами. Человек может ревьюить каждый шаг.

**Ревью против спецификации.** Автоматический ревьюер берёт **граф кода** и **граф вики** и обогащает PR: не только «есть ли баги?», но **соответствует ли это спецификации**, и нужно ли с этим выкладывать документацию.

**Публикация.** После цикла скорректированная спецификация — всё ещё вики. **Hugo** собирает **публичные документы** только из принятого git — не второй сайт, который разъезжается.

```text
созвон (WYSIWYG)  →  снимки git markdown  →  агент предлагает коммит
                                              →  человек принимает смысл (отрисованный diff + почему)
                                              →  семантический граф (связанное + история)
                                              →  план + DoD-тесты в вики
                                              →  прогон; человек ревьюит шаги
                                              →  PR-ревью, привязанное к спецификации
                                              →  Hugo из принятого git
```

## Уникальность

Чем Venus *является*. Не «лучший редактор, доска или копилот».

| | |
|---|---|
| **LLM-вики, не человеческая вики с ИИ** | Спецификация существует, чтобы агенты могли работать. WYSIWYG — как люди входят и благословляют смысл. |
| **Одна спецификация, две формы** | Живая совместная страница **и** клонируемый git markdown. Один документ. Не экспорт. |
| **Cursor для вики** | Агент правит markdown, предлагает коммит. Вы принимаете по **WYSIWYG-diff** с **почему**. Превью Cursor так не умеет. |
| **Агенты не публикуют** | Они черновик. Человек принимает смысл. Живая страница заморожена, пока они работают. |
| **Граф со временем** | Связанные клаузы **и** линия решений — не поиск и не история чата. |
| **План — это спецификация** | DoD — тесты в вики. Раннер — этот план. Люди ревьюят шаги. |
| **PR знает спецификацию** | Граф кода + граф вики. Сделанная работа привязана к плану, план — к документам. |
| **Документация — это спецификация** | Hugo публикует принятый git. Публичные документы не отстают от вики. |

## Почему это выделяется

Spec-driven development и «LLM-вики» обещают и другие. Связку — нет.

| | Они | Venus |
|---|---|---|
| **Notion** | Страница *и есть* продукт. Агент в неё печатает. Нет клонируемого дерева markdown. Большинство так и не включают Agent. | Те же жесты, чтобы комната пришла. Объект — git-спека. Агент предлагает; вы принимаете. |
| **Confluence** | Дом технического дизайна. Дамп в markdown. Не совместный созвон. | Лёгкая комната + честные файлы. Дизайн *и есть* продукт. |
| **Cursor** | Выиграл код и написание markdown. У превью документов **нет diff**. Accept живёт в исходнике. Почему — в чате. | Тот же цикл accept на вики, в WYSIWYG. Почему — на коммите. Cursor остаётся IDE, если хотите. |
| **GitBook / Tina** | Истина — git markdown. Совместная работа — ветки. Нет комнаты как в Notion. | Комната **и** git. Те, кто не пишет markdown, всё равно пишут спецификацию. |
| **Linear / Jira** | Истина — тикет. Спека — поле или ссылка. Done = карточка закрыта. Опциональный ИИ, который никто не включает. | Истина — спецификация. Доска — зеркало. Done = спека актуальна или skip. |
| **CodeSpeak** | Чат становится требованиями к **коду**. | Вики — спецификация. Чат пакует граф; он не заменяет accept. |
| **PR-боты** | Ищут баги. Не знают план и документы. Их надо было поставить. | Ревью в цикле: граф кода + граф вики, спека + документы к выкладке. |

Не покупайте Venus за совместный набор текста, канбан или более дешёвую модель. Покупайте, если агенты будут реализовывать по спецификации — и эта спецификация должна оставаться одним объектом для комнаты, git-клона, плана, PR и публичных документов.
