# M5 — plan

Four boards, in order. Design of the graph: [README](./README.md), [store.md](./store.md), [extract.md](./extract.md), [connect.md](./connect.md). Design of the cluster: [scale.md](./scale.md).

| # | Board | Status | What it lands | Why it is needed |
| --- | --- | --- | --- | --- |
| 1 | [Search cluster](./search-scale/plan.md) | In progress. Steps 1–7 done (2026-10-08). Next is [step 8](./search-scale/plan.md#8-step-query). | A graph node and two search nodes, equal copies, one fenced `layout.write` per job, and `graph_jobs` after `last_flushed`. Still to land: the router, recovery, the monitor, a third search node, three graph copies, backups, and online shard splits. | Extract and search need a place to write and a place to read. The flush must stay valid when every SurrealDB process is down. Fixtures prove the path before a real page is parsed. |
| 2 | [Extraction](./extraction/plan.md) | Not started. Starts once board 1 can take a job, which it can. Does not wait for the router, HA, backups, or shard splits. | Each committed page becomes headings, glossary mentions, code symbols, and regex mentions. `links_to` joins headings inside that page and joins pages to each other, so the wiki is one graph. One `layout.write` per page. NER stays off. | Board 1 writes fixture rows. This board is how the wiki becomes those rows, and how separate pages connect. Without the cross-links the store is a pile of pages. |
| 3 | [Graph view](./graph-view/plan.md) | Not started. After board 2 has `links_to`. | A browser view of pages, headings, in-document links, and cross-page links. Drawn with [Sigma.js](https://www.sigmajs.org/) on WebGL. Pan, zoom, and pick stay on the GPU. Layout runs in a worker. | The graph is hidden until someone can see it. A canvas 2D library stalls once the wiki is thousands of edges. WebGL is the fast path, and Sigma is the adopted engine that already draws node-link graphs that way. |
| 4 | [Tantivy](./tantivy/plan.md) | Optional. Not started. After board 1’s read path and board 2’s real text. Does not wait on the view. | Search shards become Tantivy indexes. The same item, copies, router, and split stay. Prefix search, fuzzy / edit-distance search, and segment indexing land here. The graph process stays SurrealDB. | SurrealDB `SEARCH` is whole-term BM25, updated inside the guarded write. That is fresh and expensive per document. Tantivy buffers documents into immutable segments the way Lucene does, without a JVM or a second durability log. Prefix and fuzzy come with that index. |

Board 1 is the storage and the replication. Board 2 fills it from git and ties pages together. Board 3 draws that graph. Board 4 swaps only the search index.

Semantic edges stay [connect.md](./connect.md). They are not a board yet. M6 consumes this pipeline once M5 is closed; it does not replace these boards.
